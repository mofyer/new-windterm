# 文本折叠与大纲概念验证（G16 / G17）

日期：2026-10-11。依赖：`@xterm/xterm 6.0.0`。状态：**隔离实验通过，未接生产终端；不代表 G16/G17 验收或与 WindTerm 2.7.0 的行为对照完成。**

## 要回答的问题

xterm 的公开 API 不能在实时缓冲中隐藏行，因此不能直接把 WindTerm 式折叠做在终端本体上。P0 需要确认是否存在既能折叠、又能保持选择、复制、搜索和重排一致的路线，而不是用 CSS 隐藏行冒充功能。

## 结论

**可行，但折叠需要放在由逻辑行渲染的只读历史视图里，而不是实时屏幕上。** [`fold-view.ts`](../../apps/desktop/src/terminal-compat/fold-view.ts) 把逻辑行（例如[压缩历史](HISTORY_ARCHIVE.zh-CN.md)读回的行，含颜色）写入一个只读 xterm：

- 大纲：按提示符正则把会话切成“命令 + 输出”段，可导航到行号。
- 折叠：任意不重叠的行区间显示为一行摘要（`▸ 首行 … (N 行已折叠)`）。
- 映射：视图中每个非软换行的行对应一个条目，任一视图行都能映射回原始逻辑行；改变尺寸重排后映射自动重建。
- 复制：选择覆盖到摘要行时复制完整的原始内容（折叠展开）。
- 搜索：命中折叠区时只展开该折叠，选中命中文本并滚动到位。

## 实测（headless Chrome）

| 场景 | 结果 |
| --- | --- |
| 443 行三段会话的大纲 | 三个段落的起止行与标题准确；折叠后前 6 个视图行为“提示符 + 摘要”交替 |
| 跨摘要行选择并复制 | 得到 301 行：提示符 + 被折叠的 300 行输出 |
| 在 300 行折叠区内搜索 | 返回逻辑行 272，选区文本即命中词，只有该折叠被展开，其余两段保持折叠；不存在的词返回 -1 |
| 30 → 17 列重排 | 同一逻辑行的视图行号随换行增加，行首仍是该行；跨折叠选择仍映射到 22 行 |
| 从压缩归档读回后折叠 | 443 行跨 6 个以上压缩块读回，搜索、选区与颜色（绿色提示符）保持 |

## 约束与未完成

- **实时屏幕不能折叠**：设计上，用户向上滚动进入历史时切换到该视图，回到底部时回到实时 xterm。如果 WindTerm 2.7.0 在实时区域也能折叠，需要另写 ADR（自绘渲染或替换终端组件）。
- 实验一次性渲染全部条目；生产需要只渲染视口附近的条目（虚拟化），否则大历史会让视图自身占满内存。
- 复制按整条逻辑行处理选区两端，未做列级截取；大纲靠提示符正则，未接 shell integration（OSC 133）。
- 折叠语义（复制是否展开、搜索是否自动展开、大纲层级）需与 WindTerm 2.7.0 实机对照后才能定为基线行为。
