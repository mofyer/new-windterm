## 双宽与双高：有限正向形态，精确语义未确认

```sh
printf '\033[2J\033[H\033#6DOUBLE\r\n\033#3DOUBLE\r\n\033#4DOUBLE\r\n\033#5NORMAL\r\n'
```

观察到横向放大的字形和上下部分字形，表明当前配置对相关行属性有可见响应；同时出现字形裁切、失真。不能据此确认双高上下半部正确拼接，也不能确认字符尺寸、选择、光标几何正确。

命令只输出短字符串，没有填满半行，因此**未验证半列换行/光标钳制**。不将本次形态观察写成 L01 全语义通过。当前 xterm 的已知缺口和 T07/T21 等目标继续保留。

## 左右边距：当前 linux 配置未出现预期效果

```sh
printf '\033[2J\033[H\033[?6l\033[?7h\033[?69h\033[3;6s\033[1;3HABCDEFGH\033[?69l\033[5;1H'
```

测试意图是在第 3–6 列内自动换行，期望前两行分别出现 `ABCD` 和 `EFGH`。实际观察为 `ABCDEFGH` 在同一行，没有出现所需四列换行。

这是一条**当前 linux 配置的负向结果**。未核对 VT420/VT520 模式、所有相关设置与后续编辑操作，不能推出 WindTerm 全产品不支持左右边距，也不能删除 T10/T11/T21 等冻结目标。当前 xterm 的 S04 缺口和受控分支费用继续保留。

## 矩形填充、擦除、复制：一条组合序列正向结果

```sh
printf '\033[2J\033[HABCD\r\nEFGH\033[88;1;1;2;2$x\033[1;3;2;4$z\033[1;1;1;2;;3;1;1$v\033[5;1H'
```

实际前 3 行均显示 `XX`，与这条 DECFRA/DECERA/DECCRA 组合序列的预期末态一致。这补充了上游存在相关矩形行为的有限正向证据，也支持继续保留本项目 E07 的补齐成本。

本轮没有逐步截取各条序列的中间状态，未测试重叠复制、页面参数、保护属性、坐标边界、属性变更或校验和；不能把组合末态推广为所有矩形操作或完整 VT420 通过。DECRQCRA 的默认关闭及启用门禁不变。

## 折叠：活会话中折叠已完成块后仍能输入

先运行：

```sh
printf 'P0_FOLD_BEGIN\none\ntwo\nthree\nP0_FOLD_END\n'
```

协调者点击命令行 gutter 中的减号后，原第 23–27 行显示为 `...`；第 28 行提示符仍可输入。保持旧块折叠，继续运行：

```sh
echo P0_FOLD_AFTER
```

命令和结果正常显示，旧块保持折叠。点击加号展开后，`P0_FOLD_BEGIN`、`one`、`two`、`three`、`P0_FOLD_END` 全部重新可见。

本轮证明的是**同一活会话中，已完成输出块可以折叠，同时继续输入并显示新输出**。它不证明终端控制序列如何映射到被折叠行，也未覆盖活动行重写、备用屏、全屏程序、重排、折叠选区复制、搜索、大纲或时间戳语义。没有据此断言上游一定修改了活动终端 buffer，更不能直接推导本项目必须换核。

## 对 H1+H4 的影响与停止条件

1. 保留 H1+H4 作为当前起点和条件路线建议。矩形操作得到一条有限正向证据，不能把未修改 xterm 的缺口从范围或估算中删除。
2. 双尺寸形态响应和边距单配置失败均不足以关闭精确 VT 语义。P1 对应交付前须完善验证和实现；P0 不因此扩大成全量 vttest。
3. 折叠的产品目标至少包含“旧块收起时同一会话仍可输入与输出”。现有只读历史视图原型尚未证明与实时终端的组合交互达到这一点，不能宣布 G16/G17 已对齐。
4. 可以在后续集成时评估已完成块的视图投影与实时终端协作；只有冻结行为要求修改活动行映射且现有边界无法满足时，才触发专项分支/换核评审。仍需计入这部分实现、交互及验收费用。
5. 本轮到此结束，不新增泛化探针或安装依赖。精确未知、条件费用和重新评审门禁进入[路线决定表](TERMINAL_ROUTE_DECISION_2026-10-15.zh-CN.md)，由最终出口评审决定现有证据是否足够支持保守继续。
