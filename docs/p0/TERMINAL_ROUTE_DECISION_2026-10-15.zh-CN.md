## 本次确认与路线建议

用户已确认按“终端架构关键判断、最小原生可行性、ADR 与工期”三个决策包收尾，并将真实串口验收归 P2、完整输入法/读屏/VT 验收归 P1 对应交付前。确认范围见[收尾方案](P0_CLOSEOUT_PROPOSAL_2026-10-15.zh-CN.md)；它不等于 P0 已通过，也不批准新一批合并 main。

当前建议是 **H1+H4：保留 xterm.js、补公开 API 能处理的兼容行为，并在实际集成时约束终端能力边界**。xterm 继续是唯一屏幕状态来源。H4 不要求 P0 先造抽象层，也不允许在 Rust 另维护一份活动屏幕。

依据是现有[VT 矩阵](VT_MATRIX.zh-CN.md)、[折叠](FOLDING.zh-CN.md)、[历史](HISTORY_ARCHIVE.zh-CN.md)和[内核 ADR](TERMINAL_CORE_ADR.zh-CN.md)：公开 API 能处理部分回复，现成替代内核并不覆盖所有缺口，自绘需重新承担输入、字形、选择和读屏成本。该判断支持继续使用已有路线作为起点，**不证明未修改的 xterm 能满足全部 WindTerm 语义**。

## 成本如何进入重估

[ADR](TERMINAL_CORE_ADR.zh-CN.md)中的数字保留为历史量级，供[重估](EFFORT_ESTIMATE.zh-CN.md)建立条件情景，不直接相加：

- H1+H4 的 2–4 人周不是全部终端兼容完成成本，未含所有硬缺口。只给这笔预算会漏掉双尺寸、边距、矩形及实时折叠风险。
- 受控分支 10–16 人周包含边距 3–5、双尺寸 4–6、矩形 2–3、探针/vttest 1–2 的旧估；其中边距与上游贡献 3–6 人周重叠，只能按实际采用路径去重计入。测试数字也不得再次计入阶段共用测试包。
- 每次上游合并 1–3 人周是条件维护成本，不是固定每月支出；升级次数需另设假设。
- 全换内核 6–10 人月基线加 1.5–2 人月硬缺口是替代情景，不能在已计受控分支实现之上无条件叠加。仍需考虑迁移损耗、三平台输入/无障碍及重新验收。
- 2–3 周 spike 只在证据触发并获安排后执行；不是本次新增的 P0 必做研究周期。

未决实时折叠、历史和渲染风险要在重估中有归属及条件范围，不能用“采用 xterm”将它们计为零。该表不给出新的总工期；最终数字以更新估算及独立审阅为准。

## 决定何时重新打开

[ADR 条件门禁](TERMINAL_CORE_ADR.zh-CN.md#p0-决策门禁与后续启用门禁)分别约束 P0 出口、SIXEL/CSP 启用、依赖升级、上游贡献与内核变更。最重要的边界是：

1. 新证据否定当前路线可达性，或内核补齐费用超过已评审情景时，重新评审具体修复/分支/替换建议。
2. 实时折叠若只能改变活动行映射才能满足目标，需专项 ADR；观测到当前会话继续输出不足以直接推出必须换核。
3. 插件或升级改变安全面、身份报告、输入、无障碍或状态归属时，先关闭对应启用门禁。收尾确认不豁免门禁。
4. 本文件只提供可审阅的条件决定；最终出口须把有限实测、原生可行性、费用假设与剩余风险一并交独立评审。
