# 终端 Bell 与节流设置（T27）方案与实施记录

日期：2026-11-07。分支 `p1/terminal-bell`，基于 `c24f732`。只改前端，未改 Rust、Tauri 命令、ACL 或依赖。

本记录区分三类证据：**静态证据**（只读核对 `.reference/` 下 2.7.0 发布包的配置、语言包与二进制字符串，不运行上游）、**本项目浏览器 IPC stub 证据**、**待实机核对**。浏览器测试不代表原生 WebView 能发声，也不代表与 WindTerm 2.7.0 的行为一致。T27 在[功能矩阵](../FEATURE_PARITY.zh-CN.md)中的状态不变。

## 1. 上游盘点

### 1.1 静态证据

路径缩写沿用[上游静态复核](../p0/UPSTREAM_STATIC_REVIEW.zh-CN.md#路径缩写均相对-reference)：`SCF` 为 `terminal/configs/session.config`，`LOC` 为 `global/locales/zh-CN.locale`，`BIN` 为 macOS 包主程序的 `strings` 输出（只引短语，不给行号）。

| 项 | 证据 | 静态结论 |
| --- | --- | --- |
| 配置键 | `SCF:54–55` `terminal.bellInterval: 2`、`terminal.bellStyle: 1`；macOS、Windows x64、Linux x64 三个发布包的 `SCF` 第 54–55 行相同 | 间隔与样式是会话配置（会话默认设置），三端默认值相同 |
| 自定义音效路径 | `BIN` `terminal.bellFilePath`（与上两键并列）；默认 `SCF` 中没有该键 | 存在自定义音频文件路径设置，默认未设 |
| 样式选项 | `BIN` 会话设置页名 “Bell”（与 “Connection”“Logging” 等并列），以及相邻的 “Bell styles:”、“&Mute”、“&Beep using the PC speaker”、“&Play the custom sound”；`LOC:3541` “Bell styles”→“响铃样式”，`LOC:3538` “Beep using the PC speaker”→“使用PC扬声器发出蜂鸣声”，`LOC:3619` “Mute”→“静音”，`LOC:3622` “Play the custom sound”→“播放自定义音效” | 静态可见 3 种样式：静音、蜂鸣、播放自定义音效。没有发现“视觉响铃”“闪烁窗口”一类选项 |
| 节流 | `BIN` “&Ignore bells received more than once within:”；`LOC:3604` → “忽略在指定时间内重复接收的响铃” | 有“在一段时间内忽略重复响铃”的设置，后接数值控件；单位未在相邻字符串中出现 |
| 音频资源 | `APP/global/themes/default/audios/` 下 55 个 mp3（如 “Doorbell Ring 1.mp3”） | 随包音频可供自定义音效选择；本项目不复制、不引用、不打包这些文件 |
| 信号与 VT | `BIN` `bellRequested`、`bellFilePath`；`setWarningBellVolume`、`setMarginBellVolume` | 终端内核发出响铃请求信号；方法名暗示支持 DECSWBV / DECSMBV（响铃音量控制序列），行为未知 |
| 设置作用范围 | `BIN` “The changes will be applied to NEW and all EXISTING sessions. Do you want to continue?” | 会话设置页的修改可作用于新建与全部现有会话（与 S01 共用，不特指 Bell） |

### 1.2 待实机核对

以下各项静态材料不能回答，不能从数字或字符串推断，需在上游 2.7.0 上用固定间隔 BEL 发生器、系统音量/通知条件记录与录屏核对：

1. `bellStyle: 1` 对应哪种样式。若按选项出现顺序从 0 计数会落在“蜂鸣”，但这只是推测，[基线](../p0/BASELINE.zh-CN.md)明确要求不按数字猜名称。
2. `bellInterval` 的单位（秒或毫秒）、取值范围、是否允许 0 与小数。
3. 节流窗口从哪里算起：从上一次**被接受**的响铃算起（前沿节流），还是从上一次**收到**的响铃算起（连续响铃会一直被压住）。
4. “静音”是否仍有视觉提示或标签标记；“蜂鸣”在 macOS 上是否是系统提示音（受系统提示音量与“闪烁屏幕”辅助功能影响）。
5. 非当前标签、窗口失焦或最小化时：标签有无提示、何时清除，是否有 Dock 弹跳或任务栏闪烁。
6. OSC 以 BEL 结尾时是否误响；DCS/APC 内的 BEL；DECSWBV/DECSMBV 是否真的改变音量。
7. 设置是否持久化到会话文件，默认设置与单会话覆盖的关系。

## 2. 本实现

### 2.1 样式

| 样式 | 行为 | 与上游的对应 |
| --- | --- | --- |
| 关闭 | 不发声、不做视觉提示、不标记标签；切到关闭时清除已有标记 | 对应“静音”的名称，静音是否保留其他提示待核对 |
| 视觉提示（默认） | 当前或分屏中可见的窗格边缘出现 2px 强调色内描边，300 ms 内淡出；系统开启减少动态效果时改为不动画的静态描边，在最后一次被接受的响铃后保持 1 秒再移除 | 上游没有对应选项，是本项目为可关闭、无需音频权限的默认而新增 |
| 声音 | 用 Web Audio 合成一个 880 Hz、约 120 ms 的正弦短音（峰值增益 0.12），每个会话照常节流，多个标签共用 0.4 秒发声下限 | 替代“蜂鸣”；不调用系统提示音，音量不随系统提示音量变化 |

“播放自定义音效”未实现：需要文件选择、音频解码与持久化，且不能使用上游音频文件。默认样式选视觉提示，是因为它不需要音频权限、可见可关；若实机证实上游默认是蜂鸣，是否改默认需用户决定（见第 6 节）。

### 2.2 节流语义

- 每个会话独立计时。一次响铃被接受后，该会话在“重复间隔”内收到的响铃全部忽略，窗口**从被接受的那次算起**，被忽略的响铃不延长窗口；所以持续的响铃风暴在默认 2 秒间隔下每 2 秒最多提示一次。
- 不保存窗口：每次响铃按到达时生效的间隔与该会话上次被接受响铃的时间比较，所以把间隔改短会立即生效，不会沿用旧的长窗口。
- 间隔为 0–60 的整数秒，默认 2（按上游默认值，单位假定为秒，待核对）。无论设置多少，同一会话两次被接受的响铃至少相隔 0.4 秒（`BELL_MIN_GAP_MS`），即每秒最多 2.5 次，避免 0 秒间隔时闪烁过快或连续发声。
- 声音另有全局下限：任一标签发声后 0.4 秒内其他标签不再发声，但各自的响铃仍被接受（会标记标签）。
- 一次被接受的响铃最多引起：一个 CSS 类切换（或一个短音）、一次标记重绘。被忽略的响铃只做一次时间比较，不碰 DOM。xterm.js 在解析循环里同步触发 `onBell`，处理函数用 `try/catch` 包住，异常不会中断解析或其后的 ACK。

### 2.3 哪些 BEL 会触发

由 xterm.js 6.0.0 的 VT500 状态表决定，本项目不另做解析（浏览器 stub 已逐项验证，整块、每个切点、逐字节一致）：

- 普通文本中的 BEL 触发；ESC 之后、CSI 参数中的 BEL 也被执行（VT500 行为，如 `ESC [ 3 BEL 1 m` 响一次并设置红色）。
- OSC 以 BEL 结尾**不**触发；OSC 用 ST 结束后再来的 BEL 触发。
- DCS 透传、SOS、PM、APC 字符串内的 BEL 被吞掉，不触发。
- 字节跨块到达时结果相同：会话路径先经 `Utf8Boundary`，再交给 xterm 的同一解析器。

### 2.4 非当前标签

非当前会话的响铃被接受后，其标签与侧栏行的状态点（`.status-dot`）外侧出现一圈 1.5px 强调色描边，点本身的状态颜色不变；同时在按钮内追加视觉隐藏文字“，有新响铃”供读屏。标记原地修改现有元素，不重建标签栏，不移走键盘焦点。切到该标签（点标签、点侧栏行或在分屏中聚焦其窗格）后清除；之后只有新的被接受响铃才再标记。当前会话的响铃不标记。窗口失焦时不做额外提示（没有 Dock 弹跳或任务栏闪烁）。

描边使用已有 `--accent`（设计系统只允许强调色用于状态点、选中与焦点），浅色 `#127143`、深色 `#B2CFD5`，与标签栏背景的对比度均高于 3:1。没有新增颜色、动画或通知。

### 2.5 WebView 音频解锁

`AudioContext` 只在选用声音样式后才创建。WebView 可能让新建的上下文保持 `suspended`，直到页面收到用户手势：

- 在设置面板点“应用”或“试听声音”本身是手势，此时创建并恢复上下文；
- 选用声音样式后，窗口内任意 `pointerdown` / `keydown`（包括在终端里打字）会再尝试恢复；
- 响铃时上下文未运行则请求恢复，250 ms 内未进入运行状态就丢弃这次声音，不排队补放；每次修改设置后，每种原因（挂起 / 不支持 Web Audio）最多提示一次 toast。

这些分支只在浏览器中用计数替身验证。WKWebView（macOS）、WebView2（Windows）与 WebKitGTK（Linux）的实际自动播放策略、是否真的发声、音量与系统静音的关系**均未验证**。

### 2.6 设置入口与作用范围

入口是命令面板（⌘K / Ctrl+Shift+K）中的“终端响铃设置 · 样式与重复间隔”，打开与端口转发、Telnet 同样构造的设置面板：样式下拉框、间隔输入、说明、“试听声音”“取消”“应用”。理由：应用还没有会话设置对话框（S01 未实现），侧栏底部的“外观/紧凑布局”是已认可的布局，不为单项设置改动；命令面板已承载 OSC 52 开关这类终端行为设置，键盘可达。

设置是**全局内存设置**：对已打开和新建的会话立即生效，刷新或重启后恢复默认，不写磁盘、浏览器存储或日志。上游 Bell 设置位于会话设置，本步没有单会话覆盖。

## 3. 持久化建议（本步未实现）

当前唯一的持久偏好是主题，存于 WebView 的 `localStorage`（`windterm-p0-theme`）；本地启动选项、OSC 52 开关等均只在内存。建议：

- **推荐 B：后端设置文件**。新增 Rust 命令读写应用配置目录下的版本化 JSON（例如 `settings.json` 的 `terminal.bell = { style, intervalSeconds }`），后端按同一白名单校验、原子写入、读取失败回退默认并提示。它与将来的会话配置（S01，默认会话设置 + 单会话覆盖，对应上游 `session.config`）共用一套机制，也能被多窗口共享。代价是新增命令需同步 `generate_handler!`、`build.rs` 与 capability，并补 Rust 测试。
- **备选 A：沿用主题的 `localStorage`**。实现量最小，但只在该 WebView 配置文件内、可被清除，不能与 Rust 侧会话配置共享，迁移到 B 时还需一次导入。

无论哪种，持久化前要先决定“全局默认 + 单会话覆盖”的模型、未知版本的处理，以及自定义音效文件路径是否允许（涉及文件访问与音频解码）。

## 4. 不承诺

- 不代表与 WindTerm 2.7.0 行为对齐，第 1.2 节各项均未实机核对。
- 不播放系统提示音、不使用上游或第三方音频文件，不支持自定义音效文件。
- 没有持久化、单会话设置、窗口级提示（Dock 弹跳、任务栏闪烁、系统通知）与 DECSWBV/DECSMBV 音量序列。
- 浏览器演示会话不会产生 BEL；原生 WebView 中的声音、自动播放策略和读屏朗读均未验证。

## 5. 验证（2026-11-07，本机 macOS，Chrome，IPC stub）

新增 `tests/e2e/terminal-bell.spec.ts` 14 项与 `support/bell-harness.ts`（每次 `pty_open` 独立 Channel 的 stub，以及计数用 `AudioContext` 替身；把 `session-harness.ts` 的 `exposeSessions` 导出复用）：

1. 默认视觉提示：单次 BEL 闪一次、不发声、不标记、ACK 照常。
2. 同块 200 个、逐块 20 个、文本夹带 20 个，共 240 个 BEL 在默认间隔内只提示一次，无 toast，ACK 逐块按序。
3. 间隔 1 秒：0.5 秒处的响铃被忽略且不延长窗口，1.25 秒处被接受；间隔 0 时连发 20 个只算一次，0.45 秒后再接受。
4. 关闭样式：不提示、不发声、不标记，切换为关闭时清除已有标记；原始 `onBell` 照常计数。
5. 声音样式：替身计数，会话节流与跨标签 0.4 秒发声下限；无视觉提示；只创建一个上下文。
6. 上下文挂起：不补放、只提示一次；窗口内点击后恢复，再响铃才发声。
7. 没有 Web Audio：只提示一次不可用，终端输出与 ACK 不受影响。
8. 非当前标签：标签与侧栏标记、读屏文字；连续响铃不重建标签栏、不移动焦点；切换（标签或侧栏）后清除，新响铃再标记。
9. 分屏中可见的非当前窗格：既闪烁也标记，聚焦后清除。
10. 12 组样本（OSC/DCS/SOS/PM/APC/CSI/ESC/多字节文字）整块、每个切点、逐字节送入，`onBell` 次数一致且符合第 2.3 节。
11. 减少动态效果：静态描边、`animation-name: none`，连续响铃期间不熄灭，停止后移除一次。
12. 设置面板：命令面板入口、5 种非法间隔报错、取消不生效、试听、对新会话生效、刷新后恢复默认且浏览器存储中无相关键。
13. 关闭带标记或正在提示的标签：状态释放，无页面错误。
14. 模块单元（假时钟）：前沿窗口、改短间隔立即生效、0.4 秒下限、关闭、标记只一次、宿主异常不外抛、`forget` / `dispose` 释放订阅、提示与窗口监听、表单校验。

独立代码审查（只读）结论为无阻塞问题，提出两项中等：一是窗口级手势监听不能移除，已加 `dispose()`（`AbortController`）并纳入第 14 项；二是认为改间隔后旧窗口仍生效，核对后不成立（窗口不保存，见第 2.2 节），以第 14 项改短间隔的断言固定该行为。

结果：`npm run build` 通过；新增 14 项 `--repeat-each 5` 共 70 次通过；本机全量浏览器 E2E 551/551（`c24f732` 实测基线 537 + 14）。反向验证：把节流改为“从最近收到的响铃算起”后第 3、14 项失败；把标记改为整体重绘标签栏后第 8 项失败（均已还原）。界面截图（浅色/深色标签栏与侧栏标记、静态描边、设置面板）只作作者自查，未入库。

未运行：Rust 门禁（未改 Rust）、原生 WebView（声音、自动播放策略、读屏）、跨平台 CI、上游实机对照。

## 6. 待用户决定

1. 默认样式：保持“视觉提示”，还是在实机确认上游默认后改为“声音”。
2. 持久化方案：推荐 B（后端设置文件，与 S01 会话配置共用），或先用 A（`localStorage`）。
3. 是否需要窗口级提示（Dock 弹跳 / 任务栏闪烁）；需要时用 Tauri 的 `requestUserAttention`，要新增 capability 权限。
4. 是否安排一次上游 2.7.0 实机核对（第 1.2 节七项），再据此调整节流语义与样式对应。
