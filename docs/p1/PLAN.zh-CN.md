归属：[估算](../p0/EFFORT_ESTIMATE.zh-CN.md) A1 应用/终端边界与 A2 本地 Shell 的部分工作。当前启动失败后输入仍可能缓存，初次 resize 错误可能覆盖退出状态；正常退出没有明确恢复入口。

交付范围：

1. 启动失败成为明确终态，停止接收输入并清空启动前队列。

4. 提示当前终端已结束、输入不会发送，正常运行时不展示误导性恢复操作。

验证：浏览器 IPC 契约覆盖失败、退出、重复点击、输入不重放、resize/exit 竞态和既有关闭行为；Linux/Windows 原生 WebView 场景扩充真实退出码、重新打开和 shell 输出读回。浏览器契约不代表原生通过；macOS 完整原生、IME/读屏和性能仍需对应交付验收。

本批不改变 Shell 启动参数、持久设置、主题和传输功能，不声明 T01/T34 或 A1/A2 整包完成。产品代码修改经独立审查、合并后本机门禁及跨平台 CI；不修改冻结台账状态。

1. 保留一键默认本地终端入口，增加显式启动目录输入；留空使用现有默认目录。
2. Rust 按当前平台校验绝对路径和目录，直接传入进程创建参数，不展开变量或 `~`，不拼接 shell 命令，不改变应用全局工作目录。校验时无效的目录必须报错。锁定的 portable-pty 0.9.0 会对失效 cwd 回退到 HOME/USERPROFILE，因此创建前再次校验；外部进程恰在最后校验与库内检查之间删除或改名的竞态仍需明确记录，不能宣称已彻底消除。
3. 目录字符串中的合法空格及中文原样传递；Windows 相对盘符路径、根相对路径及当前 cmd.exe 不支持的目录形式明确报错。
4. 重新打开继承原会话的启动目录，创建新的 PTY；随后编辑表单不能改变已有会话的启动配置。
5. 浏览器测试证明输入与 IPC/重新打开契约；真实 PTY 和 Linux/Windows 原生 WebView 读回 shell 的实际目录，覆盖退出后重新打开。两类证据分别记录。

并行职责：`p1/cwd-backend` 负责 Rust 校验与 IPC；`p1/cwd-ui` 负责界面、会话配置及浏览器契约；`p1/cwd-native` 负责真实 PTY/原生场景。协调者负责独立审查、集成、全套门禁与 CI。全部通过后取得本批单独批准并合入 main，未沿用第一批批准。

## 第四批：会话环境变量与 locale（2026-10-18 开始）

P0 已关闭，P1 前三批已获单独批准并合并，main 产品基线为 `780a10e`。本批从第三批文档提交 `780a10e` 开始，后端、界面及原生验收在三个隔离工作树并行实施，产品代码已独立审查并集成至 `bea905f`。会话环境变量与 locale 已实现，本机全套门禁与 macOS 有限原生验收通过；Windows 旧 Shell 场景曾在目录查询时停滞，根因未定，不能称整批验收完成。最新 CI、追踪与待完成项统一见 [执行记录](RESULTS.zh-CN.md)。第四批继续在集成分支推进，尚未获 main 合并批准，不能沿用第三批授权。

1. 环境变量用名称/值条目编辑，不解析 shell 文本；值保留空字符串、中文、空格和等号，禁止 NUL。普通变量最多 64 项、名称最多 64 字节、单值最多 4096 UTF-8 字节；普通变量与 locale 合计按每项名称字节数 + 值字节数 + 2 计，不超过 16 KiB。Windows 按 ASCII 大小写不敏感规则拒绝重复，Unix 保留大小写语义。
2. locale 分默认与自定义。默认保留平台现有设置；自定义先清除默认注入的 `LANG`/`LC_*`，再设置选定变量，空列表表示全部清除。仅接受 `LANG`、`LC_ALL` 和列出的 11 个分类变量；拒绝 `LC_ALL` 与其他 `LC_*` 并存，允许 `LANG` 与 `LC_ALL` 并存并说明后者优先。Windows 仅传递变量，不等同于修改代码页或 PowerShell 显示语言。
3. 每会话保存独立配置，重开继承最初配置，不继承交互命令的 `export`/设置结果，不重放输入。修改表单只影响新会话。应用不将变量值写入日志、状态文案或持久设置；这不承诺 Shell、用户命令或操作系统不会记录这些值。
4. 保留运行、提示符、历史路径及启动加载相关变量，普通环境编辑不能绕过本批受控启动策略；`PATH` 可显式覆盖，但 Shell 候选解析仍使用固定绝对路径。保留项与禁止前缀以后端验证为准。此为本切片支持边界，不删除完整 WindTerm 目标；任意环境变量也不能被宣称对后续用户命令没有影响。
5. 浏览器验证 IPC、字面值、表单错误、深复制与重开；真实 PTY 和三端原生分别验证子进程读回、会话隔离、默认兼容及退出后重开。错误与反序列化信息不得回显变量值。既有 owner/generation、容量、ACK 和关闭回收门禁继续执行。

完成实现后分别独立审查，集成树执行全套门禁，再推送和触发本批 CI；原生证据与浏览器替身证据分开记录。启动后执行命令另做切片，先复核 Windows Job 收养竞态、就绪时机和显式执行语义。持久配置、完整 T34、P1 与发行验收均不在本批宣告完成；合并 main 前仍单独确认。

下一切片只读准备发现：`pty_open` 返回后已完成 Windows Job 收养，但不能据此证明 Shell 已在提示符就绪，也不能声称消除初始化阶段的派生进程竞态。此前路径分析曾发现 early 输入队列可能混合用户输入与终端 CPR 应答；当前实现已限制 early FIFO 仅接收本地 shell 的显式 CPR reply，用户输入不得进入。启动命令若直接插入，仍可能与其他启动期副作用交错，而 xterm 的 `disableStdin` 又会阻断 CPR。实施前须定义输入来源门控、同一 FIFO 中的一次发送、失败/重开是否执行及用户可见语义，并用实际副作用次数验证；不把提示符、首次输出或固定延时当通用就绪协议。本轮仅完成输入来源门控，尚未交付启动后命令功能。
