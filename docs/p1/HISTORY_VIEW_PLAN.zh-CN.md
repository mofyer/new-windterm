## 2. 入口

- **终端工具栏**：在 `.terminal-tools` 行新增文字按钮「历史与搜索」，放在「清除与复位」左侧，`aria-pressed` 表示当前标签的视图是否打开，再点一次关闭。理由：这一行是“作用于当前会话”的动作区（重新打开、端口转发、清除与复位），查找在上游也是作用于当前终端的动作；工作台没有菜单栏和终端右键菜单；文字按钮与同一行其他按钮一致，不新增图标或营销式入口。按钮由新模块以 DOM API 插入，未改 `main.ts` 模板。
- **命令面板**：一条「历史与搜索 · 当前会话 · 含已压缩的历史」。命令面板是工作台已有的全局动作入口（⌘K / Ctrl+Shift+K）。
- **快捷键：未添加**（待决问题 1）。上游 `Ctrl+Shift+F` 在 Windows/Linux 上需要从终端按键里拦截；现有键盘测试与 T31（键盘与初始模式，另一代理并行）都在这一区域，本次不碰终端按键处理。

## 3. 视图形态：覆盖本会话终端窗格的只读面板

视图是一个放在**该会话自己的终端窗格**内、覆盖整个窗格的面板（`position: absolute; inset: 0`）。选择理由：

1. **不改变终端尺寸**。侧边或底部面板会让终端变窄或变矮，触发 fit → `*_resize` → 主机重排（SIGWINCH）和热历史重排，这本身就是对终端状态与主机的修改。覆盖层不改变窗格大小，终端照常渲染、解析输出与 ACK。
2. **历史行宽与终端一致**。终端行往往很宽，侧栏放不下；文件检查器那样 244px 的侧栏不适合阅读历史。
3. **与预案第 8 节的模型一致**：越过热窗口的浏览、搜索（以及以后的折叠、大纲）由只读投影承担，回到终端即回到活动 xterm。
4. **分屏与标签**：视图属于会话、放在会话窗格里，分屏时只覆盖该会话的窗格，另一个窗格照常可用；切换标签时随窗格隐藏、切回时仍在原位置（隐藏期间记住位置，重新显示时恢复）。同一会话的元素仍只在一个窗格中，视图是只读投影，符合预案第 7 节第 2 条不变量。

视图打开期间，终端元素设为 `inert`：被覆盖、看不见的终端不能获得焦点或接收按键（否则用户以为在输入搜索词，字符却发给了 Shell）。`inert` 只是 DOM 属性，不改 xterm 的任何状态；关闭视图时移除。若程序开启了焦点报告（DECSET 1004），焦点从终端移到视图会照常让 xterm 发出一次失焦报告，这与点击工作台其他控件相同。

视图组成（自上而下）：标题行（「历史」、会话名、“第 a–b 行 · 共 n 行”、「刷新」、关闭）、提示行（见第 5 节，没有提示时隐藏）、查找行（搜索框、「区分大小写」与「正则」切换、状态、「上一处」「下一处」「停止」「复制所选行」）、行列表。

## 4. 热历史、冷归档与屏幕如何拼成连续行号

- **不是“热 + 冷”两段拼接**。第 5 步起，归档在每个逻辑行离开屏幕时写入，热窗口里的 5,000 行在归档中已经有一份（压缩）。所以视图的历史部分全部从归档读：`[first, end)`，`first` 是最早仍保留的行（之前的被预算丢弃或被用户清除），`end` 是已归档行数。
- **屏幕部分**：尚未归档的逻辑行（屏幕上的行，以及最近一次捕获之后才写出的行）经终端内核边界的新只读方法 `HistorySource.unread()` 从 xterm 普通缓冲读取，起点与下一次 `read()` 的续读位置相同，但不移动归档的 marker、不消耗待处理的复位/清除标记、不写终端。光标以下的空行不计入。备用屏（vim、less）期间读的仍是普通缓冲，备用屏内容不进入视图。
- **行号**：从会话历史的第一行起计数（显示时从 1 开始），归档行与屏幕行连续编号，因为屏幕行以后归档时得到的正是这些号码。被丢弃、被清除的行保留其号码位置，所以视图可以从“第 7,681 行”开始。**缺口中丢失的行没有号码**：号码按历史中保存的行计，不按主机发来的行计。行号是逻辑行（自动换行的多行合为一行），不是终端行。
- **快照**：打开或「刷新」时取一次快照（`first`、`end`、标记、屏幕行的副本）。之后的新输出不并入视图，只在提示行说明“打开后有新输出，点「刷新」查看”；归档此后若按预算丢弃了快照范围内的行，读到它们时显示“此行已不在历史中（已丢弃或已清除）”，提示行说明丢弃了多少行；用户执行「清除回滚」/「全部清除」时快照里的归档行全部失效，视图自动刷新并发通知。「刷新」保留当前选中行和搜索词，并在新快照上重新搜索。
- **没有归档的会话**：演示会话没有冷归档，捕获出错停止的会话也没有；视图改为读取该终端普通缓冲的全部逻辑行（经边界的 `xtermBufferLines`），从 1 编号，提示行写明“此会话没有压缩历史 / 历史记录已停止，只显示终端中的 N 行”。

## 5. 清除与缺口如何呈现

归档新增“标记”：每次捕获报告缺口或清除时，在下一行之前记一条（`HistoryArchive.held().marks`），只追加；被预算丢弃的行之前的标记随之删除；用户清除时全部删除；每个归档最多保留 4,096 条，更早的计数并在提示行说明。视图把标记画成占一行的灰底说明行（不可选中，读屏为禁用选项）：

| 情况 | 视图中 |
| --- | --- |
| 捕获缺口（行在归档前已被 xterm 裁掉，如一次写入超过热窗口、REP 造成的超长行） | 说明行“此处有缺口：部分输出在保存进历史之前已被终端裁掉”，位于缺口之后的第一行之前 |
| 主机或用户的复位（RIS、硬复位）与主机的清除回滚（ED 3，如 `clear`） | 说明行“此处终端被复位或清除了回滚；以上各行只保留在历史中”。归档保留之前的行（T32 方案 A），终端里已经没有它们 |
| 屏幕行开始处 | 说明行“以下为打开历史时的屏幕内容” |
| 屏幕行的起点不确定（`unread` 报告位置未知） | 在屏幕说明行之前加一条缺口说明行 |
| 最早的行被预算丢弃（决定 3A） | 第 0 行说明“第 1–N 行已因超出历史预算丢弃”；提示行“最早的 N 行已不在历史中：N 行超出历史预算已丢弃” |
| 用户「清除回滚」/「全部清除」（T32） | 第 0 行“第 1–N 行已清除（清除回滚）”；二者都有时“第 1–N 行已不在历史中（已丢弃或已清除）”，提示行分别给出两个数字 |

## 6. 搜索语义

- **纯文本**（默认）：查询词按字面匹配。实现上把它转义为不含量词、分组或分支的正则（带 `u` 标志），匹配时间与行长成线性关系，任何输入都不会造成灾难性回溯。
- **正则**：「正则」切换开启后，查询词是 JavaScript 正则表达式，只在专用 Web Worker 中编译与匹配，每批行设超时，主线程不执行用户正则（第 16 节）。下列大小写、范围、跨行、宽字符、顺序、上限、起点与取消规则两种模式相同。
- **大小写**：默认不区分，「区分大小写」切换后立即重新搜索。不区分时用 Unicode 简单大小写折叠（例如不会把 “ß” 与 “SS” 视为相同）。不提供全词匹配、选区内查找与增量查找。
- **范围**：快照中的全部行，即保留的冷归档（逐块按需解压）加屏幕行；SGR 已去掉，只匹配文字。不搜索已丢弃、已清除的行，不搜索备用屏。
- **跨行与跨块**：匹配不跨逻辑行（硬换行结束一行）；终端自动换行的多行已合成一个逻辑行，所以跨软换行的匹配能找到。归档块只含整行，块边界不会切开匹配。
- **宽字符与列**：按文字匹配，宽字符、组合字符、emoji 都按其文字比较，与占几个单元格无关；宽字符换行时 xterm 留下的填充格不在归档里，不会把“漢字”切开。命中位置以“第 N 行”报告并在行内高亮，不报告列号。
- **顺序与上限**：从最新的行向最旧的行搜索（屏幕行，然后归档从新到旧逐块），每处命中按行内从右到左收集，因此超过上限时保留的是**最新的** 10,000 处（`HISTORY_SEARCH_MAX_MATCHES`），状态写“已达上限，只列出最新的 10,000 处”。每次匹配不重叠。
- **起点**：新搜索选中视口底部所在行或其上方最近的一处命中；没有时选其下方最近的一处。视图从最新行打开，所以通常是最新的一处。搜索中途若用户移动（键盘、点击、滚轮），搜索不再自动移动视图。
- **长搜索与取消**：搜索在每块之间以及至少每 8 ms 让出一次事件循环（`MessageChannel`），终端输出的解析、ACK 与输入照常进行。新搜索、「停止」、刷新、关闭视图、关闭标签都会中止正在进行的搜索；中止后不会再改动视图。停止后状态为“已停止：已找到 N 处（未搜索完）”，再按 Enter 重新搜索。

## 7. 跳转与预览（G21 的本次形态）

- 「上一处」（Enter、F3）向上即更早，「下一处」（Shift+Enter、Shift+F3）向下即更新，两端循环。状态写“第 k 处，共 N 处”，k 从最早一处数起。
- 跳转只移动视图，不滚动终端：命中行不在视口内时滚到视口中部，当前命中加强调色描边，其他命中为浅色底；横向滚动使当前命中可见；选中行随之移到命中行（便于复制）。
- 本次的“预览”就是视图本身：命中行与上下文在同一列表中按原顺序、原颜色显示，行号与终端内容一致。上游的 “Find All / Preview All” 式结果列表（带前后若干行上下文）没有做（待决问题 3）。
- 行内显示上限 2,000 个 UTF-16 单元（`HISTORY_VIEW_MAX_CHARS`）：更长的行显示前 2,000 个字符并注明“本行共 N 个字符”；当前命中在截断处之后时，改为显示命中附近的一段。搜索与复制总是用整行。

## 8. 复制、键盘、焦点与读屏

- **复制**：选中行后用「复制所选行」或 ⌘C / Ctrl+C 复制完整逻辑行（SGR 已去掉，行间以 `\n` 连接），归档行按需读出。单次最多 50,000 行（`HISTORY_COPY_MAX_LINES`），超出时拒绝并提示，不截断；选区中已被丢弃的行不复制并在通知里给出数量。在行内拖选文字时，复制交给 WebView 自己处理（只含可见部分）。通知只有行数，不含历史文字。剪贴板写入用 `navigator.clipboard.writeText`。
- **键盘**：搜索框中 Enter / Shift+Enter；视图内任意处 F3 / Shift+F3、⌘F / Ctrl+F 回到搜索框、Esc 关闭；行列表中 ↑ ↓ PageUp PageDown Home End 移动当前行，加 Shift 扩展选区，⌘A / Ctrl+A 全选，⌘C / Ctrl+C 复制；点击行选中，Shift+点击扩展。Tab 在搜索框、按钮与行列表间移动。
- **焦点返回**：Esc、关闭按钮或再次点击工具栏按钮关闭视图后，焦点回到该会话的终端。视图打开时，选择该标签、关闭对话框或执行 T32 动作后的焦点都回到视图的搜索框，而不是被覆盖的终端（`main.ts` 的 `focusActive`）。
- **读屏**：视图是带名称的 `region`；行列表是 `listbox`（可多选），只渲染的可见行是 `option`，带 `aria-posinset` / `aria-setsize` 与“第 N 行 …”的名称，当前行经 `aria-activedescendant` 指向；说明行为禁用选项；搜索状态是 `role="status"` 的礼貌播报，搜索中至多每 400 ms 更新一次。以上只按 ARIA 写法实现，**没有**用 VoiceOver、NVDA 或 Orca 验收（P1 第 6 片）。

## 9. 性能与内存预算

| 项目 | 做法与上限 |
| --- | --- |
| 渲染 | 固定 20px 行高虚拟化：DOM 中只有视口内的行加上下各 12 行（实测 12,001 行时 72 个行元素）。滚动高度最多 8,000,000 px，更长的历史按比例滚动（60 万行时约 13 px/行），键盘与跳转仍落在确切的行上 |
| 解压 | 只解压视口与搜索用到的块；渲染用归档已有的两块解码缓存，搜索按块解码且不写入该缓存，不会挤掉正在显示的块 |
| 视图缓存 | 已解析的行最多 2,048 行且合计不超过约 4M 个 UTF-16 单元，超出按最久未用淘汰；单行过长不缓存 |
| 搜索 | 命中最多 10,000 处，每处 3 个数字；逐块扫描并让出事件循环；可取消 |
| 屏幕快照 | 屏幕行的字符串副本，最多为屏幕行数加一个跨入屏幕的长逻辑行 |
| 压缩队列中的块 | 归档新增“读取等待压缩的块”：已封口但仍在压缩队列里的块直接从原始字节读出，不必等压缩完成（第 5、6 步时 `lines()` 在高输出下会漏掉这些行）。没有增加内存：这些原始字节本来就在队列里 |
| 关闭释放（R2） | 视图挂在会话的关闭路径上（`Session.historyView`，在冷归档之前释放）：中止搜索、释放快照、行缓存与监听，移除覆盖层 |

视图不在 xterm 写入回调或 ACK 链中做任何事。它只订阅一次 `onWriteParsed`（经边界的 `observeWrites`，每帧至多一次，回调只设标志并以 200 ms 合并更新提示行）。

## 11. 不承诺的事项

- 不是第二份终端：视图不解析字节流、没有输入路径、不保存光标或模式；不能在视图里输入、执行或编辑。
- 不滚动、不选中、不修改终端；跳转只在视图里。
- 不实时跟随新输出（快照）；不显示备用屏内容；不搜索已丢弃或已清除的行；缺口不能补回。

- 不代表 Q06、G20、G21 已对齐或验收；原生 WebView 中的剪贴板、内存与性能未测。

## 16. 正则搜索（2026-11-07，用户决定第二组第 12 项）

分支 `p1/history-regex`，基于 `p1/integration` 的 `9ba1ad3`。只改前端，未改 Rust、Tauri 命令、ACL、CSP、Vite 配置与依赖。证据全部来自系统 Chrome（Vite 开发服务器 + IPC stub，另有一次生产构建临时检查），**不是**原生 WebView 结论。

### 16.1 入口与语义

- 查找行「区分大小写」右侧新增文字切换「正则」（`aria-pressed`，与「区分大小写」同一样式与按下态；按去模板化约定不用 `.*` 之类文字字形当图标，没有新增图标，`icons.ts` 未改），默认关闭。关闭时走原来的纯文本搜索函数与转义，行为不变；开启时占位符改为“正则表达式”。有查询词时切换立即重新搜索，与「区分大小写」相同。
- 输入框的全部内容就是正则的 source，**不解析 `/…/flags`**（斜杠属于模式），用户不能指定标志。标志固定为 `g`、`u`，不区分大小写时加 `i`；**不使用 `v`**（应用最低 macOS 13.3 的 WebKit 相当于 Safari 16.4，不支持 `v`），也不使用 `s`、`m`、`y`、`d`。`u` 下为严格的 Unicode 语法（例如字符类外的 `\-` 无效），`.` 与字符类按码点匹配、不切开代理对，忽略大小写用 Unicode 简单大小写折叠，与纯文本搜索一致。每个逻辑行单独匹配，`^`、`$` 即行首、行尾，匹配不跨行。
- **后顾（lookbehind）**、前瞻、命名组与反向引用原样交给 WebView 的正则引擎：Chrome 与 WebView2 支持后顾（本次在 Chrome 中验证）；WKWebView 自 Safari 16.4 起支持，与最低系统版本相同；WebKitGTK 取决于发行版的 WebKit 版本，不支持时编译失败并显示“正则表达式无效”。三种原生 WebView 均未实测。
- 零长度匹配（`^`、`a*` 落在没有 `a` 处等）不计为命中，因为无法高亮；因此不能用 `^$` 找空行。匹配不重叠。
- 命中上限（最新 10,000 处）、从新到旧顺序、新搜索的起点、跳转与循环、行内高亮、复制整行，都与纯文本搜索相同：两者产出同一种结果结构，由视图同一段代码处理。
- 状态行只由固定文字和数字组成，不回显查询词，也不显示引擎的英文错误消息：

| 情况 | 状态行 |
| --- | --- |
| 模式无法编译 | “正则表达式无效，请检查括号、量词与转义”，搜索框 `aria-invalid="true"` |
| 某批超过时间上限 | “匹配超时，已停止：第 k 处，已找到 N 处（未搜索完，一批行超过 1 秒）” |
| Worker 无法启动（加载失败、CSP 拒绝、5 秒内没有应答） | “正则搜索不可用：后台线程未能启动” |
| 引擎抛错或应答不合法 | “正则匹配出错，已停止：第 k 处，已找到 N 处（未搜索完）” |

超时或出错前已找到的命中仍可用「上一处」「下一处」浏览；与“已停止”相同，在搜索框按 Enter 会重新搜索。

### 16.2 Worker 设计

- `history-regex-worker.ts` 是专用 module Worker，也是**唯一**编译与执行用户正则的地方；`history-regex-protocol.ts` 只有消息类型，不含运行代码，主包不包含匹配代码。
- `history-regex.ts`（主线程）：每个视图一个 `RegexWorker`，第一次正则搜索时才创建，同一时刻只有一个请求在途。`searchHistoryRegex` 走与纯文本搜索相同的行（屏幕行，然后归档 `scanBackward` 从新到旧逐块按需解压），在主线程用 `plainText` 去掉 SGR，只发送行文本：每批最多 512 行（`ARCHIVE_BLOCK_LINES`）且合计最多 65,536 个 UTF-16 单元，更长的单行单独一批。编译消息只有 `kind/search/source/caseSensitive`，匹配消息只有 `kind/search/batch/lines/limit`，不发送颜色、行号或其他数据。
- Worker 返回扁平的 `[批内行号, start, end]`，按批内从新到旧、行内从右到左排列，最多返回仍缺少的命中数（每行只保留最右边的若干处，内存有界）。主线程核对搜索号与批号、条数上限，以及每处是整数、非空、在该行长度之内，不合格即作为“出错”终止 Worker，然后才换算为绝对行号。
- 时间上限（`history-budget.ts` 的命名常量）：`HISTORY_REGEX_BATCH_TIMEOUT_MS = 1_000`（每批匹配）、`HISTORY_REGEX_START_TIMEOUT_MS = 5_000`（加载 Worker 脚本并编译）、`HISTORY_REGEX_BATCH_CHARS = 65_536`（每批文本量）。计时在主线程，到时立即 `terminate()`，不论引擎正在做什么。1 秒是每批上限，不是整次搜索的上限。
- 终止：搜索运行期间在其 `AbortSignal` 上挂监听，「停止」、新查询（含切换大小写或正则）、「刷新」、Esc / 关闭按钮 / 工具栏按钮关闭视图、关闭标签与页面卸载（经 `Session.historyView` 的释放路径）都会立即 `terminate()` 正在工作的 Worker；超时、Worker `error` / `messageerror`、不合法应答也终止。正常结束的搜索保留空闲 Worker 给下一次查询，视图 `dispose` 时一并终止。下一次正则搜索时重建。
- 主线程从不编译或执行用户正则：纯文本路径仍只编译转义后的字面量；正则路径只发送字符串。若原生环境中 Worker 无法启动，只显示“不可用”，不会退回主线程执行。

### 16.3 CSP

**未改动**。`tauri.conf.json` 的 `csp` 与 `devCsp` 都是 `default-src 'self'; script-src 'self'; …`，没有 `worker-src`；按 CSP Level 3，Worker 脚本回退到 `script-src 'self'`，允许同源脚本。Vite 生产构建把 Worker 打包为同源文件 `assets/history-regex-worker-<hash>.js`（1.1 KB，IIFE，无导入、无 `eval`），主包以 `new Worker(new URL(...), { type: "module" })` 引用；不使用 `blob:` / `data:` Worker，`new RegExp` 不受 CSP 限制，也不需要 `unsafe-eval` 或 `wasm-unsafe-eval`。因此不需要最小修改，未运行 `cargo check`（Rust 与 Tauri 配置均未改）。

Chrome 中的证据（不是原生）：

1. 新增 E2E：探针页以生产 CSP 作为响应头，经应用模块完成一次三行正则搜索，结果与预期逐项相同；对照组在同一策略后追加 `worker-src 'none'`，结果为“不可用”，说明策略确实约束 Worker 且失败路径可用。
2. 临时检查（未进测试集）：`vite preview` 提供生产构建，首页响应加上生产 CSP 头，演示会话中正则搜索得到 2 处、无效模式提示正确，Worker 地址为 `/assets/history-regex-worker-hRwqpflR.js`；唯一的 CSP 违规是检查脚本故意发起、用来证明策略生效的 `fetch`（被 `connect-src` 拦截）。

**未验证**：WKWebView（`tauri://localhost` 自定义协议）、WebView2（`http://tauri.localhost`）与 WebKitGTK 中能否加载 module Worker，以及 Tauri 在运行时改写 CSP（注入 hash / nonce）后是否仍放行。
