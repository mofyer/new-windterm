# 界面与交互设计方向

状态：P0 进行中。Silver Soft UI 已实现白色画布、银白浮层、24px 主面板圆角与双向柔影，薄荷/绿色仅用于局部强调；用户已明确回复“接近了，按这个方向继续”，认可该视觉方向。这不等于完整功能或可访问性验收完成。
`apps/desktop` 已有可运行界面与本地 PTY 原型。以下是设计目标和验收要求；最新实现范围见[原型说明](p0/UI_MAP.zh-CN.md)，验证与未完成项见 [P0 结果](p0/RESULTS.zh-CN.md)。
具体视觉参数见[设计系统](p0/DESIGN_SYSTEM.zh-CN.md)。最新白银浮层版 56 项浏览器测试在 16.2 秒内通过，无测试放宽（53 项正向/契约，含 2 项对比度检查；2 项兼容缺口；1 项旧 Unicode6 反例）；所测颜色对最低对比度为浅色 4.674:1、深色 4.640:1。详见[测试报告](p0/WEB_QA.zh-CN.md)；新版原生冒烟已有记录，完整原生专项仍待验收，颜色检查不是完整无障碍认证，反例通过不能计为功能完成。

## 设计目标

完整保留 WindTerm 功能语义、安全边界与专业操作效率，允许重新组织视觉和入口，无需复刻旧界面的像素布局。
以[功能矩阵](FEATURE_PARITY.zh-CN.md)追踪现有 117 项及后续盘点补充项，不因简洁外观删除功能或让功能失去可发现入口。
Rust + Tauri 2 + xterm.js 路线保持；苹果风描述体验方向，不等于 SwiftUI/AppKit 控件实现。

## 建议布局

| 区域 | 建议 | 保留的操作能力 |
| --- | --- | --- |
| 标题栏 | 统一标题栏与系统窗口控制，工具按钮克制 | 窗口管理、全局搜索和常用操作 |
| 左侧栏 | 可收起的会话树与分组，宽度可调 | 会话管理、切换、搜索与连接状态 |
| 中央工作区 | 终端为主，标签页与分屏可组合 | 多会话、tmux、选择、滚动和输出工作流 |
| 文件检查面板 | 按需打开的文件 inspector，可调整宽度 | 本地/远端浏览、文件操作和传输入口 |
| 底部传输栏 | 活跃任务摘要，可展开完整队列 | 进度、取消、失败原因和结果反馈 |

折叠面板保留明确的重新打开入口；需要确认或处理的任务不得仅藏在收起区域。
优先紧凑、可调的信息密度；高密度会话树、多标签和分屏不为装饰性留白牺牲可用空间。

## 建议视觉

- 当前原型首次默认浅色，提供深色、跟随系统及偏好持久化；最终默认策略随用户确认调整。
- 采用低饱和中性色和少量强调色，连接、风险和错误状态同时提供文本或图形线索。
- 圆角、阴影和动效保持克制，重点是层级与可读性。
- UI 使用系统字体；终端采用可配置等宽字体，验证中文、emoji、字体回退和列宽。
- 半透明限于界面装饰层，终端默认使用高可读的实底；保留窗口透明度功能的明确设置入口。
- 提供减少透明度、减少动态效果、增强对比度和清晰键盘焦点的适配，验证偏好变化后的可用性。

## 交互与平台约定

每个重设计入口应记录“功能 ID → 新位置/命令 → 键盘方式”，可通过界面或命令搜索发现，不能只靠记忆快捷键。
快捷键按焦点与模式路由，避免 UI 截获终端 Ctrl-C 等交互；应用菜单、终端输入及本地编辑模式的冲突需明确测试。
危险操作、主机信任、凭据保存和同步输入保留明确状态与确认，不用视觉简化弱化安全信息。
macOS 优先遵循本地操作习惯；Windows/Linux 使用各自窗口控制和键盘约定，不机械套用 Mac 窗口按钮。
专业流程允许紧凑模式和面板快捷切换；入口重组后应对比完成相同任务的步骤与键盘效率。

## 阶段与验收

P0 已具备主工作区、会话配置、分屏和模拟文件传输交互原型；重设计已覆盖浅深色、紧凑布局与关键确认状态并完成浏览器回归。视觉方向已获用户认可，下一步沿该方向完善并补齐原生专项验收。
P0 同时记录入口与功能 ID 的映射、快捷键冲突、字体与透明度风险；静态稿通过不代表终端或功能已经实现。
P4 落实设计，分别保留功能报告与视觉报告：

- 功能报告验证各 ID 的行为、安全和效率，没有因视觉重组漏项。
- 视觉报告检查浅深色、字体回退、缩放、紧凑布局、可读性、焦点和减少透明度/动态效果等偏好。
- 键盘报告验证完整流程可触达、焦点可见且能返回终端，Ctrl-C 等终端组合键不被误截获。
- 平台报告记录真实设备与系统版本，macOS 结果不直接充当 Windows/Linux 验收。
